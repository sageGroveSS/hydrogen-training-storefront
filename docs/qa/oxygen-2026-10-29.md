## Published storefront — layout and accessibility

HTTP 200 and no document-level horizontal overflow at 320, 390, 768 and 1440 CSS px:

- `/`
- `/collections/sofas`
- `/products/luna-modular-sofa`
- `/search?q=sofa`
- `/pages/contact`
- `/wishlist` (guest, empty)
- `/cart` (guest, empty)

Axe WCAG 2 A/AA and 2.1 AA scan found insufficient contrast on the PDP's crossed-out
price (3.37:1) and the review score caption (4.34:1). The other six sampled pages
had no violations under those selected tags; this is not a screen-reader audit or
proof of full WCAG conformance. Lighthouse additionally flags skipped heading levels
(product cards/options) and the wishlist button's visible/accessibility label mismatch.

## Confirmed remaining findings

1. **Homepage hydration:** React error #421 occurred in both Lighthouse and the
   browser sweep. This indicates a Suspense boundary updated before hydration
   finished. Investigate provider updates around deferred/lazy sections; the audit
   does not establish the exact source of that update.
2. **SEO on this host:** `/robots.txt` responds with `Disallow: /`; normal document
   responses carry `x-robots-tag: none`. `/sitemap.xml` returns 404. Home, product
   and Contact do not have a rendered canonical link; collection does. The technical
   host's indexing restriction affects the SEO scores. Confirm intended indexing
   policy/domain before changing it.
3. **Accessibility:** fix the PDP contrast, wishlist label mismatch and heading
   hierarchy described above, then repeat keyboard and assistive-technology checks.
4. **Cache policy verification:** PDP and wishlist document responses explicitly use
   `private, no-store`; `/account` redirect also does. The anonymous `/cart` document
   has no explicit Cache-Control header. This is a missing explicit guard to review,
   not evidence that personal data was served from a shared cache. Storefront query
   caching and full HTML response caching must be checked separately.

## Limits

No authenticated customer writes, cross-device wishlist sync, live review submission,
moderation mutations, real payment, Safari/iOS hardware or screen-reader session were
included. Previously user-verified account/review behavior is not a substitute for
an automated authenticated acceptance test. Field INP requires real interaction
telemetry; TBT above is only a lab proxy. Repeat checks on the final deployed content
page and final public domain before sign-off.
